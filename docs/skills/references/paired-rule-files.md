# 税务规则成对文件：复刻修复 + 行错位核对

## 两个规则文件的关系（2026-08 实测）

- `txcs-interceptor-rules - 蓝色海洋20260808.json` 与 `txcs-interceptor-rules - 海盛和食品20260808.json`
  **索引一一对齐**（各 176 条），同一索引在两文件里是同一份规则的两个副本。
- 每份文件都包含：本公司规则（enabled=True）+ 对方公司规则（enabled=False，保留作对照/备用）。
- 蓝色海洋文件的蓝色海洋规则 158-165/174 是 enabled；海盛和文件里同样索引是 disabled 且**可能是修复前的旧数据**。
- alias 命名两文件可能略异（如 V2 规则：蓝海文件 "蓝色海洋-25年12月-V2增值税及附加税费申报表(V2)"，海盛和文件 "蓝色海洋-25年12月-增值税及附加税费申报表(V2)"）——**复刻时只同步 response，保留目标文件 alias/pattern/enabled**。

## 行错位修复模式（25年12月 V2 + 26年6月 均中招）

生成器 `gen_tax_from_pdf.py` 的 lcs_map 会把"有数据行"（栏1）的值错误复制到多个全 0 行。已发案：
- 附列资料一：栏3/7/12/15 被填栏1 数据（26年6月还波及栏11）；栏3 特殊情况是 9%货物行真有小值 41.28/3.72，别整体清零
- 附列资料二：栏15/17/18/21/22/28/31（26年6月为 14/15/20/21/32）被填"份数+金额"（如 58/3,018,063.62、59/8,213,320.87）
- 申报表：39 栏被填成 40 栏的值（两文件都犯）
- 26年6月申报表 18 栏实际抵扣税额被填 0.00（应为 823,678.75）

**核对法（每次生成/修复后必跑）**：
1. 非零值反向核对：规则里每个非零数值都能在 PDF 对应行找到；PDF 全 0 的行规则里必须全 0
2. 份数是裸整数（58/59/5），正则要 `\d+`（`\d+\.\d{2}` 匹配不到）——校验脚本里份数会误报差异
3. PDF 文本层可能损坏数字：26年6月 栏18 文本层 "823,678,75"（小数点变逗号），用视觉或四则校验（19=11-18）确认
4. 视觉复核：`pdftoppm -png -r 150` 渲染页面 + 小米 MiMo（config.yaml auxiliary.vision，mimo-v2.5，max_tokens 3000），prompt 按"栏次=本月数,本年累计数"输出

## HTML 修复函数要点

```python
def fix_tr_rn(html, rn, td_repls):
    pat = re.compile(r'<tr[^>]*rn=\\?"' + rn + r'\\?"[^>]*>[\s\S]*?</tr>')
    # repl 里必须 open_tag + body + '</tr>' 三段拼接，漏 </tr> 会破坏 HTML
```
- HTML 里 rn 引号是转义形式 `rn=\"16\"`，正则用 `rn=\\?"16\\?"`
- td 值可能带 `\n` 换行（`\n\n590,158.56\n\n`），按 rn+td 索引整体替换不受影响
- 修复前 `cp 文件 /tmp/xxx.bak.json`；assert 每处 rn 只匹配 1 次；修复后对比 tr 数量不变

## 实例：海盛和 25年12月 附列资料（二）
